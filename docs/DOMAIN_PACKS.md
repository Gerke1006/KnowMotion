# 学科包与内容覆盖

统一流程读取 `domains/<domain>/pack.json`、`plan.md`、`styles/default.json`、`components/registry.json`、`examples/*.json`、`audio/profile.json` 与 `renderers/default.json`。学科包负责教学顺序与内容约束；渲染器负责把组件数据变成动画。模型不直接生成并执行任意 Python。

| 学科 | 本地 demo 课程 | 重点视觉组件 | 专业约束 |
| --- | --- | --- | --- |
| 数学 | 微积分的本质、导数、积分、勾股定理 | 割线趋近切线、黎曼矩形、三角形与面积、公式 | 定义域、极限条件、示例与证明分开 |
| 历史 | 丝绸之路 | 时间线、关系网络 | 年份和出处；网络示意不冒充地理地图 |
| 物理 | 牛顿第二定律 | 过程图、变量图表、公式 | 单位、惯性系、恒定质量等理想化条件 |
| 生物 | 光合作用 | 流程图、结构关系、总反应式 | 标明尺度，区分物质流和能量流 |
| 经济学 | 供需关系 | 假设数据图表、因果关系 | 明确假设，模型不冒充现实数据 |
| 文学 | 比喻的表达 | 文本与意象关系 | 原创句与原文区分，解释须受语境约束 |

demo 只使用人工编写课程，不调用模型或付费配音。未知主题明确报错，并列出当前学科的可用示例。参考链接在 demo 产物中标记 `reference_not_fetched`，不宣称本次联网核验。

live 模式由模型识别主要学科；研究阶段从 Wikipedia API 检索中文和英文页面并记录实际返回的 URL、摘要和获取时间，然后要求模型基于这些材料整理知识。它目前是单一资料提供方，不能替代历史研究中的多来源交叉考证；网络失败或没有来源时停止生产并报告错误。资料整理与教学规划不是运行时 AI 审片。

每个场景的 `domain` 独立解析，所以数学视频也能包含历史时间线。`extensions` 保存学科扩展字段；`visual_plan` 使用对应 Pack 的相机、声音与风格数据（`extensions.visual_style`），保留原始教学计划。用户指定渲染器属于执行选项，不改变场景学科。

`assets/catalog.json` 支持按学科、场景、动画类型和素材类别检索。优先选择完整组件，其次组合声明支持目标组件的基础素材，最后记录通用绘图候选。检索元数据不会让尚未实现的动画自动获得执行能力：具体可执行语法与限制以 `renderers` 为准。仓库没有附带第三方视频、音乐或字体文件；外部参考只是链接，音频通过配置加载。

参考了 [manim-video](https://github.com/browser-use/video-use/tree/main/skills/manim-video) 的独立场景生产方式、几何直观与统一语义配色，参考了 [motion-showreel](https://github.com/ConardLi/garden-skills/tree/main/skills/motion-showreel) 的对象状态变化和共享时间轴思路。这里按项目要求采用一键执行，省去其交互确认与审片步骤；没有复制参考视频或源码。

运行 `python domains/build_catalog.py` 可从版本化的人工课程数据重新生成包和目录。修改已有 JSON 后不要随意运行此命令，以免被生成源覆盖；长期修改应同步维护生成源。通过 `tests/test_planning.py` 检查学科路由、全部 demo 课程、跨学科分镜、检索层级、资料来源和数学示例参数。
